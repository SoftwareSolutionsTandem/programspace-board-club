# Игротека (рабочее название) — правила для ассистента

- Общение с владельцем — на русском. Код, идентификаторы и коммиты — на английском; комментарии в коде — на русском.
- Перед работой прочитать `docs/PROGRESS.md` и `docs/ROADMAP.md`. После работы обновить `PROGRESS.md` и, если менялись решения, `DECISIONS.md`.
- Документы: концепция `docs/CONCEPT.md`, архитектура `docs/ARCHITECTURE.md`, звук `docs/AUDIO.md`, стиль `docs/ART_STYLE.md`, персонажи `docs/CHARACTERS.md`, правила `docs/games/*.md`, компоновки `docs/LAYOUT.md`, платформа `docs/YANDEX.md`, монетизация `docs/MONETIZATION.md`.

## Команды
- `npm run dev`, `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`; `npm run check` — всё сразу (как CI).
- Продукты (`docs/ARCHITECTURE.md` §8): `npm run build:durak`, `npm run build:dominoes`, `npm run build:all` → `dist/<id>/`; `npm run check:bundle` — состав сборок. Ключ настроек «Игротеки» `igroteka.settings` не менять. Игры продукта — `src/products/<id>.games.ts`; приложение работает с игрой только через `src/app/game.ts`.
- Перед коммитом — `npm run check`. Браузерная проверка — Playwright против `npm run preview`, без ошибок в консоли.

## Ветки и PR (D47)
- `main` — стабильная проверенная версия; меняется только через PR с зелёным CI и одобрением владельца. Прямых отправок в `main` нет.
- Одна рабочая ветка на крупную задачу, имя `work/<задача>` (сейчас — `work/stage-2`). Мелкие правки и исправления по замечаниям — в неё же.
- Новая ветка — только для срочного исправления `main`, пока рабочая не готова, или для параллельной задачи, которую владелец явно запустил. Не создавать ветки без необходимости.
- Один PR на ветку; цепочек PR (PR в ветку другого PR) нет.
- Изменения между ветками не переносить по коммитам (cherry-pick). Обновить рабочую ветку из `main` — только слиянием `main` в неё. Историю рабочей ветки не переписывать, force-push запрещён.
- После слияния ветка удаляется в тот же день.
- Неодобренная работа в `main` не попадает (выключенной — только с явного согласия владельца).
- В конце каждой задачи сообщать: ветка, последний коммит, отправлен ли он, состояние CI.

## Нерушимые правила
- Персонажи говорят голосом. Текстовые облачка вместо речи запрещены. Заглушки и пустые файлы не выдавать за озвучку.
- Аудио без записи в `assets/audio/LICENSES.md` в сборку не попадает.
- Беззвучный режим устройства и ограничения браузера на автозапуск звука не обходить.
- Правила игр (`src/games/*/rules`) — чистые функции: без DOM, звука, таймеров и `Math.random()`. Случайность — только ГСЧ из состояния.
- ИИ получает только `PlayerView`. Импорт полного состояния в `ai/` запрещён. Тесты неразличимости обязательны.
- API Яндекс Игр — только в `src/platform/yandex.ts`.
- Любое изменение формата сохранений → поднять версию и добавить миграцию с тестом.
- Игра для телефона **и** компьютера. Правила, ИИ, состояние, контроллер и аудио не знают о размерах экрана. Геометрия — только из `computeLayout` (`docs/LAYOUT.md`).
- Реклама — никогда во время партии.
- Варианты правил не менять без записи в `docs/games/*.md` и `DECISIONS.md`.
- Не называть этап завершённым без запуска тестов, typecheck и сборки. В отчёте отделять проверенное от непроверенного.
- Код и материалы проекта Oil Tycoon не использовать.
