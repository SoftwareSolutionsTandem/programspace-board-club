# Архитектура

Статус: **согласована как предварительная, под вертикальный срез**; параметры уточняются измерениями (этап 1c). Абстракции появляются только тогда, когда их требует реальная задача. Например, общий интерфейс игрового модуля оформляется, когда начнётся вторая игра.

## 1. Стек (предварительный, уточняется прототипом)
| Слой | Выбор | Почему | Что проверяем прототипом |
|---|---|---|---|
| Язык и сборка | TypeScript (strict) + Vite | быстрая разработка, статическая сборка в zip для Яндекс Игр | размер бандла, время старта |
| Сцена партии | PixiJS v8 | WebGL-рендер, хорошо держит анимацию персонажа и карт на телефонах, MIT | FPS и время кадра на слабом Android, память текстур |
| Экраны и меню | HTML/CSS поверх сцены | чёткий текст, вёрстка, доступность, i18n | безопасные зоны, поворот экрана |
| Анимации | свой небольшой модуль твинов на тикере Pixi | без лишней зависимости | хватит ли его для эмоций персонажа |
| Аудио | своя тонкая обёртка над Web Audio API | шины, приоритеты и приглушение пишем сами | задержка, декодирование, iOS |
| Тесты | Vitest (+ Playwright для смоук-проверок в браузере) | чистые функции правил тестируются без браузера | — |

Новые зависимости — только с проверкой лицензии и записью в `DECISIONS.md`.

## 3. Поток данных в партии
```
ввод (указатель, касание, клавиатура) → намерения игрока / ход ИИ
        │ Action
        ▼
rules.apply(state, action) ──► новое состояние + [доменные события]
        │                                  │
        │ projectView(seat)                ├──► scene: анимация карт
        ▼                                  ├──► director: эмоция + заявка в VoiceChannel
     ИИ.decide(view)                       └──► ui: HUD, кнопки, результат
```
- Правила ничего не знают о сцене, звуке и платформе.
- Сцена может «проигрывать» события с задержкой (анимация), но состояние истины — в правилах. Ввод блокируется, пока анимация ключевого события не завершена.
- Ход ИИ запрашивается контроллером после анимаций. Время раздумья добавляется для драматургии и на решение не влияет.

## 3а. Адаптивная компоновка (телефон и компьютер)
Полная спецификация — `docs/LAYOUT.md`. Коротко:
- Две основные компоновки — `portrait` (телефон) и `landscape` (компьютер) — плюс промежуточные `portrait-wide` и `landscape-compact`. Расположение зон перестраивается, а не масштабируется.
- **Не зависят от экрана и способа ввода:** правила, ИИ, состояние партии, контроллер, режиссёр реакций, аудиосистема. Размеры экрана в них не передаются.
- `computeLayout(viewport) → LayoutSpec` — единственный источник геометрии. Pixi-сцена раскладывает объекты по нему, HTML-интерфейс получает те же прямоугольники через CSS-переменные.
- Ресайз и поворот: `ResizeObserver` + `visualViewport`, пересчёт не чаще одного раза за кадр. Объекты переезжают к новым целям анимацией, состояние партии и звучащая реплика не прерываются.
- Ввод: указатель, касание и клавиатура превращаются в одни и те же намерения (`selectCard`, `playSelected`, `take`, `pass`, `pause`, `toggleSound`). Контроллер принимает только намерения.
- Текущий каркас (этап 1.1) пока раскладывает сукно одинаково для всех экранов. `computeLayout` появится вместе со сценой партии.

## 5. Сохранения
- Формат `{ version, settings, progress }`, где `settings` — громкости и «без звука», `progress` — серии и статистика.
- `version` растёт при каждом изменении структуры. Миграции хранятся цепочкой `vN → vN+1`.
- Повреждённые или неизвестные данные → безопасное начальное состояние + запись в журнал. Игра стартует и без сохранений.
- Локально — `localStorage` через адаптер. Облако Яндекса — на этапе 6, через тот же интерфейс.

## 6. Производительность (гипотезы, подтверждаются измерением)
- Цели (проверяются на прототипе, затем фиксируются):
  - 60 FPS на десктопе;
  - стабильные 60 FPS (минимум 30) на Android среднего уровня;
  - время кадра в отладочной панели.
- Стартовая загрузка: только ядро и ассеты Агаты. Остальные персонажи догружаются лениво.
- Векторные слои персонажа при загрузке растеризуются в текстуры нужного разрешения (с учётом devicePixelRatio).

## 7. Отладка и проверка
- `?debug` — панель: FPS, время кадра, текущее состояние партии, журнал событий и реплик.
- `?seed=N` — воспроизводимая раздача.
- `?layout=portrait|landscape|…` — принудительная компоновка для отладки.
- Объект `window.__game` (только в dev-сборке) для Playwright-проверок.
