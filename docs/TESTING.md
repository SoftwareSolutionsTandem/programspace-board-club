# Тестирование

## Автоматические проверки
| Проверка | Команда | Что ловит |
|---|---|---|
| Линтер | `npm run lint` | ошибки кода; **Math.random() и DOM в чистом коде** (`src/core`, `src/layout`, `src/games/*/rules`, `src/games/*/ai`, `src/games/*/view.ts`); **импорт полного состояния партии в ИИ** |
| Типы | `npm run typecheck` | строгий TypeScript (`strict`, `noUncheckedIndexedAccess`) |
| Тесты | `npm test` | Vitest, файлы `tests/**/*.test.ts`, окружение Node |
| Сборка | `npm run build` | production-сборка Vite |
| Всё сразу | `npm run check` | то же, что задание `check` в CI (`.github/workflows/ci.yml`) на каждый PR и push в `main` |
| Браузер (e2e) | `npm run test:e2e` | Playwright против production-сборки (`vite preview`), Chromium, компьютер 1280×720 и телефон 390×844 (касания); задание `e2e` в CI |

- `tests/layout/layout.test.ts` — компоновка: 14 экранов × 2 типа указателя, 500 случайных размеров, большая рука до 30 карт, безопасные зоны, флаг «слишком маленькое окно».
- `tests/games/durak/interaction.test.ts` — касания, перетаскивание, подсказки, подсветка.
- `tests/games/durak/tutorial.test.ts` — подсказки обучения по ситуации, каждая один раз.
- `tests/render.tween.test.ts` — твины: цель, задержка, замена, «без движения», finishAll.
- `tests/e2e/game.e2e.ts` (Playwright, оба профиля):
  - полная партия только через интерфейс (мышь на компьютере, касания на телефоне), экран результата, реванш, возврат в клуб;
  - поворот и изменение размера посреди партии: рука и счёт сохраняются, все карты руки на экране;
  - клавиатура (компьютер): стрелка + Enter, «Беру» — T;
  - недопустимый ход: подсказка, состояние не меняется;
  - настройки переживают перезапуск; честная пометка об отсутствии записей голоса;
  - отказ загрузки всех аудиофайлов и манифеста — игра идёт без ошибок;
  - первый запуск: подсказки обучения и пропуск;
  - слишком маленькое окно: подсказка, после увеличения партия на месте;
  - большая рука (10+ карт): точки касания карт попадают в сцену, партия доигрывается;
  - высокая плотность пикселей (2,625, телефон): сцена строится, ход проходит.
  Сторож в `playThroughUi` падает сразу, если интерфейс 12 попыток подряд не продвигает партию, и пишет, что лежит в точках касания.
  Проверки ходят через `window.__igroteka()` — там только проекция игрока, без руки Агаты и колоды.
  Без GPU (контейнер, CI) Chromium рисует WebGL программно (SwiftShader): сцена партии идёт ~6–10 кадров/с, каждый вызов к странице — до 0,5 с. Поэтому нажатия в e2e — касанием или кликом по координатам элемента (для карт руки — по их видимой части), а полная партия имеет таймаут 8 минут. Профиль телефона идёт с плотностью пикселей 1: при плотности Pixel 7 (2,625) пикселей вчетверо больше и полная партия в CI не укладывалась в таймаут. Высокую плотность проверяет отдельный короткий сценарий. О производительности на устройствах эти цифры ничего не говорят.

## Чего текущие проверки НЕ подтверждают
- Качество и синхронизацию **голоса**: записей пока нет, голосовой канал проверен только модульными тестами.
- Работу в Safari/iOS и Firefox: e2e идут только в Chromium.
- Плавность на слабых телефонах: FPS и память меряются вручную.
- Удобство и понятность — это ручные проверки с людьми.

## Ручная проверка в VS Code
1. `npm install`, затем `npm run dev`, открыть адрес из консоли.
2. Для телефонных размеров: DevTools → режим устройства (например, 390×844) и альбомная ориентация.
3. Отладка: `window.__igroteka()` в консоли — экран, компоновка, настройки и проекция партии для игрока (без скрытых карт).
4. Демонстрация e2e с окном браузера: `npx playwright test --headed --project=phone`.

Автотесты логики звука **не заменяют** прослушивание: качество голоса проверяется вручную на телефоне и в наушниках.
